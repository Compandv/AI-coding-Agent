# MewCode 第三章规格说明：工具系统

## 背景
MewCode 前两章已经具备常驻式终端界面、真实模型流式回复和进程内多轮上下文，但它仍然主要是一个聊天机器人。第三章的目标是让 MewCode 具备工具系统：模型可以在回答过程中请求执行某个能力，程序负责执行工具，把结果回灌给模型，再由模型基于结果给用户最终回复。

这一章的重点不是完整自动循环，而是打通“模型提出工具调用、程序执行工具、模型得到工具结果后回答”的最小闭环。完成后，MewCode 将从只能聊天升级为可以读写项目文件、修改文件、搜索代码和执行受控命令的早期 Agent。

## 目标用户
- 想让终端 AI 助手真正操作项目文件的开发者。
- 正在学习 Coding Agent 工具调用架构的人。
- 需要理解工具接口、工具注册、权限边界和模型工具结果回灌流程的开发者。

## 阶段目标
本阶段要交付一个统一工具系统。用户提出需求后，模型可以选择一个工具，MewCode 执行该工具并把结构化结果放回对话上下文，然后模型基于这一次工具结果生成最终回答。工具能力限定在启动 MewCode 时的当前工作目录内。只读工具可以自动执行；写文件、改文件和命令执行属于敏感能力，需要默认经过用户确认。

## 能力清单
- MewCode 可以向模型暴露一组统一描述的工具能力。
- 每个工具都有名称、用途说明、参数约束和执行逻辑。
- MewCode 可以集中登记工具，并按模型请求的工具名查找对应工具。
- MewCode 可以把已登记工具转换为模型 API 可识别的工具描述。
- 模型可以请求读取当前工作目录内的文件内容。
- 模型可以请求在当前工作目录内创建或覆盖文件。
- 模型可以请求通过唯一原文匹配的方式修改当前工作目录内的文件。
- 模型可以请求在当前工作目录内执行受控命令。
- 模型可以请求按路径模式查找文件。
- 模型可以请求搜索文件内容。
- 工具执行失败时，MewCode 会把失败原因结构化返回给模型，而不是让程序崩溃。
- 工具执行有超时保护，避免单次工具调用无限阻塞界面。
- MewCode 可以解析模型流式返回中的工具调用信息，并拼接完整参数。
- 工具结果会回灌进当前对话历史，让模型基于结果生成最终回答。
- 本章每轮用户请求最多执行一次工具调用，自动多步循环留到后续章节。

## 非功能要求
- 工具接口应统一，方便后续新增更多工具。
- 工具注册中心应避免交互层直接依赖具体工具实现。
- 工具执行结果应清晰区分成功、失败、输出内容和错误原因。
- 文件路径必须限制在启动 MewCode 时的当前工作目录内。
- 只读工具应尽量减少打断，敏感工具应默认需要用户确认。
- 命令执行应有超时、输出截断和错误返回，避免阻塞或刷屏。
- 文件修改必须避免模糊替换，匹配不到或匹配不唯一时应让模型重新尝试。
- 工具调用过程应能在 Textual 界面中被用户观察到。
- Provider 层应尽量屏蔽不同模型供应商的工具调用协议差异。
- 本章实现应为后续 Agent Loop 预留扩展空间，但不提前实现循环。

## 设计骨架
MewCode 第三章按以下层次组织：

1. 工具抽象层
   - 负责定义工具需要具备的元信息、参数约束和执行能力。
   - 负责统一工具输入、工具输出和错误表达。

2. 核心工具层
   - 负责实现文件读取、文件写入、文件修改、命令执行、路径匹配和内容搜索等基础能力。
   - 负责路径约束、超时控制和失败信息整理。

3. 工具注册层
   - 负责集中登记所有可用工具。
   - 负责按名称查找工具。
   - 负责把工具集合转换成模型可识别的描述。

4. Provider 工具调用适配层
   - 负责把注册中心中的工具传给模型。
   - 负责解析模型流式返回中的工具调用事件。
   - 负责把工具结果转换回模型后续请求可接受的上下文消息。

5. 会话与编排层
   - 负责在一轮用户请求中识别是否发生工具调用。
   - 负责执行一次工具调用并记录工具结果。
   - 负责让模型基于工具结果生成最终回答。

6. Textual 交互层
   - 负责展示工具调用状态、等待确认、执行结果摘要和最终回答。
   - 负责让用户对敏感工具进行确认或拒绝。

## 权限与边界
- 只读类工具可以自动执行。
- 写文件、改文件和命令执行默认需要用户确认。
- 文件类工具只能操作当前工作目录及其子目录。
- 命令执行需要受超时和错误处理保护。
- 本章不做持久化权限记忆，确认只对当前工具调用有效。

## Out of Scope
- 不做自动多轮 Agent Loop。
- 不做同一轮内连续多次工具调用。
- 不做长期权限记忆。
- 不做远程主机命令执行。
- 不做后台任务队列。
- 不做项目索引数据库。
- 不做 Git 自动提交或自动推送。
- 不做复杂 diff 审阅界面。
- 不做多 Agent 协作。
- 不做图片、语音、文件上传等多模态工具。

## 完成定义
当用户提出需要查看、搜索、创建、修改文件或执行命令的请求时，模型可以发起一次工具调用，MewCode 能根据权限边界执行或请求确认，并把结构化工具结果回灌给模型生成最终回答，则本章达到核心完成标准。验收还需要证明：工具接口统一，注册中心可用，六个核心工具可观测，路径限制生效，敏感工具确认生效，工具失败不会导致程序崩溃，并且本章没有实现自动多步循环。
