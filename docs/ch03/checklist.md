# MewCode 第三章验收清单：工具系统

## 工具接口验收
- [ ] 项目中存在统一 Tool 抽象，且每个工具都暴露名称、描述、参数 Schema 和执行方法。
- [ ] `grep -R "class .*Tool\|def .*execute\|schema" src/mewcode/tools` 能看到统一工具接口和工具实现。
- [ ] 工具执行结果使用结构化格式区分成功、失败、输出内容和错误原因，而不是只返回一段普通字符串。

## 六个核心工具验收
- [ ] 工具注册中心中可见这六个工具名称：`ReadFile`、`WriteFile`、`EditFile`、`Bash`、`Glob`、`Grep`。
- [ ] `grep -R "ReadFile\|WriteFile\|EditFile\|Bash\|Glob\|Grep" src/mewcode` 返回不少于 6 处工具定义或注册位置。
- [ ] 模型可识别的工具列表中包含六个工具，且每个工具都带有参数 Schema。

## 路径边界验收
- [ ] 文件类工具只能访问启动 `mewcode` 时的当前工作目录及其子目录。
- [ ] 当模型请求读取当前目录外路径时，工具返回结构化拒绝结果，而不是直接读取成功。
- [ ] 当模型请求写入当前目录外路径时，工具返回结构化拒绝结果，而不是直接写入成功。
- [ ] 使用相对路径访问当前目录内文件时，工具可以正确解析并执行。

## ReadFile 验收
- [ ] 当模型请求读取当前目录内已存在文件时，工具返回文件内容。
- [ ] 当模型请求读取不存在的文件时，工具返回结构化错误，并包含文件不存在信息。
- [ ] 当模型请求读取目录而不是文件时，工具返回结构化错误，而不是崩溃。
- [ ] 读取成功时，结果中包含被读取的目标路径。

## WriteFile 验收
- [ ] `WriteFile` 被标记为敏感工具，默认需要用户确认。
- [ ] 用户确认后，工具可以在当前目录内创建新文件。
- [ ] 用户确认后，工具可以覆盖已有文件内容。
- [ ] 用户拒绝时，文件不会被创建或修改，且拒绝结果会结构化返回给模型。
- [ ] 写入失败时，错误会被结构化返回，而不是让程序崩溃。

## EditFile 验收
- [ ] `EditFile` 被标记为敏感工具，默认需要用户确认。
- [ ] 当 `old_string` 在目标文件中唯一匹配一次时，工具完成替换并返回成功结果。
- [ ] 当 `old_string` 在目标文件中匹配不到时，工具返回结构化错误，并明确说明未匹配到原文。
- [ ] 当 `old_string` 在目标文件中匹配多次时，工具返回结构化错误，并明确说明匹配不唯一。
- [ ] 用户拒绝 `EditFile` 时，文件不会被修改。

## Glob 验收
- [ ] `Glob` 可以按模式查找当前目录内路径，例如 `src/**/*.py`。
- [ ] `Glob` 返回的是路径列表，而不是整个文件内容。
- [ ] 当没有匹配结果时，工具返回空结果而不是报错崩溃。
- [ ] `Glob` 不会返回当前工作目录外的路径。

## Grep 验收
- [ ] `Grep` 可以在当前目录内搜索文件内容。
- [ ] 搜索结果至少包含文件路径、行号或匹配文本摘要中的一种可观察信息。
- [ ] 当没有匹配结果时，工具返回空结果而不是崩溃。
- [ ] 当搜索模式非法时，工具返回结构化错误，并让模型可据此重试。

## Bash 验收
- [ ] `Bash` 被标记为危险工具，默认需要用户确认。
- [ ] 用户确认后，工具可以在当前目录内执行命令并返回退出码、stdout、stderr。
- [ ] 用户拒绝时，命令不会执行，且拒绝结果会结构化返回给模型。
- [ ] 当命令超时后，工具返回结构化超时错误，而不是无限挂起。
- [ ] 当命令退出码非 0 时，工具不会导致程序崩溃，而是把失败结果结构化返回给模型。

## 工具注册中心验收
- [ ] 项目中存在一个集中登记工具的注册中心。
- [ ] 注册中心支持按工具名查找工具。
- [ ] 注册中心支持列出所有工具并转换为模型 API 可识别的工具描述。
- [ ] 当模型请求未知工具名时，程序返回结构化错误，而不是抛出未处理异常。

## Provider 工具调用验收
- [ ] MewCode 可以把已注册工具转换成 Claude 或 OpenAI 可识别的工具描述并随请求发送。
- [ ] 流式工具调用中的 JSON 参数碎片会被正确拼接成完整参数对象。
- [ ] 工具执行完成后，工具结果会被追加到当前对话历史中。
- [ ] 模型拿到工具结果后，会基于该结果生成最终回答。
- [ ] 当工具调用参数不合法时，失败信息会被结构化回灌给模型，而不是直接中断会话。

## 单次工具调用边界验收
- [ ] 一轮用户请求中，模型最多执行一次工具调用。
- [ ] 工具结果回灌后，本章流程会停在最终回答，不会继续自动发起第二次工具调用。
- [ ] 文档和实现中都明确说明自动 Agent Loop 留到下一章。

## 权限确认验收
- [ ] `ReadFile`、`Glob`、`Grep` 这类只读工具可以自动执行。
- [ ] `WriteFile`、`EditFile`、`Bash` 默认执行前都会要求用户确认。
- [ ] 用户确认界面或提示中能清楚显示将要执行的工具名称。
- [ ] 用户拒绝敏感工具后，模型能收到结构化拒绝结果并调整回答。

## Textual 界面验收
- [ ] 当模型请求工具时，Textual 界面中能看到当前正在调用工具的状态或提示。
- [ ] 当工具需要确认时，界面中能看到确认请求，而不是在后台静默等待。
- [ ] 当工具执行成功后，界面中能看到工具结果摘要或随后出现的模型最终回答。
- [ ] 当工具执行失败后，界面中能看到失败信息或随后出现的模型调整后回答。

## 错误处理验收
- [ ] 工具执行异常不会把 Python traceback 直接暴露给用户。
- [ ] 文件不存在、路径越界、替换不唯一、命令超时、命令失败、未知工具等场景都有结构化错误返回。
- [ ] 当模型收到工具失败结果后，MewCode 不会退出，而是继续保持会话可用。

## 启动与主流程验收
- [ ] 运行 `mewcode` 或 `python -m mewcode` 后，现有 Textual 主界面仍然可以正常启动。
- [ ] 当前对话主流程不再只是单纯聊天，而是能够让模型请求并使用工具。
- [ ] 启动时会创建工具上下文、注册中心和单次工具编排流程。

## 范围边界验收
- [ ] `grep -R "while .*tool\|agent loop\|auto loop" src/mewcode` 不会显示已经实现自动多轮工具循环的主流程代码。
- [ ] 本章不会在未经确认的情况下自动执行 `WriteFile`、`EditFile`、`Bash`。
- [ ] 本章不会把权限确认持久化到下次启动。

## 端到端验收
- [ ] 在一个示例项目目录启动 `mewcode`，输入“读取 README.md 内容”，观察到模型触发一次 `ReadFile`，工具结果回灌后给出最终回答。
- [ ] 输入“搜索项目里哪里定义了 Provider”，观察到模型触发 `Grep` 或 `Glob`，然后基于结果回答。
- [ ] 输入“创建 notes.txt 并写入 hello”，观察到界面先请求确认；确认后文件被创建，随后模型给出完成回答。
- [ ] 输入“把某文件中的唯一原文替换掉”，观察到 `EditFile` 只在唯一匹配时成功；匹配不到或匹配多次时，模型收到错误并改口说明。
- [ ] 输入“执行 pwd”或等价安全命令，观察到 `Bash` 请求确认；确认后命令结果回灌，模型基于输出回答。
- [ ] 在同一轮中工具执行完成后，模型给出最终回答并停止，不会继续自动发起下一次工具调用。
