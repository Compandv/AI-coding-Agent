# MewCode 第四章规格说明：Agent Loop

## 背景
MewCode 第三章已经具备工具系统，模型可以发起一次工具调用，程序执行工具并把结果回灌给模型。但第三章仍然是“一步一停”的最小闭环：一轮用户请求最多执行一次工具，执行完成后就要求模型给出最终回答。

第四章的目标是给 MewCode 装上 Agent Loop，让它从能调用工具的聊天助手升级为能自主干活的早期 Coding Agent。模型可以连续读代码、搜索项目、写文件、运行命令、观察结果并决定下一步，直到任务完成或触发停止条件。

## 目标用户
- 想让终端 AI 助手自主完成多步编程任务的开发者。
- 正在学习 Claude Code 类 Agent Loop 架构的人。
- 需要理解事件流、工具批处理、模式切换和 UI 解耦方式的开发者。

## 阶段目标
本阶段要交付一个顺序 ReAct Agent Loop。用户提出任务后，MewCode 调用模型，收集模型输出和工具调用，执行一批工具，把结果写回会话，再继续请求模型。循环在任务完成、模型不再请求工具、达到步数上限、用户取消或发生不可恢复错误时停止。

本阶段同时引入 Plan Mode。用户通过命令切入只规划不执行的模式后，Agent 只能使用只读工具理解项目，并输出计划；写文件、改文件和命令执行会被拦截。本阶段不实现完整权限系统，也不再保留第三章的用户确认机制。

## 能力清单
- MewCode 拥有独立 Agent 组件，负责持有模型客户端、工具注册中心、运行上下文和循环配置。
- Agent 使用 ReAct 范式驱动多步循环。
- Agent 可以在同一轮用户请求内连续执行多个模型请求和多个工具步骤。
- Agent 在每轮模型响应中可以收集文本增量和工具调用。
- Agent 可以把模型文本增量实时透传给 UI。
- Agent 可以把工具轮中的中间文本展示给用户，但不写入会话历史。
- Provider 可以表示同一次模型响应中的多个工具调用。
- 会话历史可以表达一次 assistant 工具响应对应多个工具调用。
- 会话历史可以把多个工具结果按原始工具调用顺序回填给模型。
- Agent 可以把工具调用分为安全读工具和不安全工具。
- 安全读工具可以批量并发执行。
- 不安全工具按模型请求顺序串行执行。
- 正常执行模式下，写文件、改文件和命令执行会自动运行。
- Plan Mode 下只允许只读工具。
- Plan Mode 下不安全工具会被拦截并作为结构化结果回灌给模型。
- 用户可以通过命令在 Plan Mode 和正常执行模式之间切换。
- Agent 通过事件流向 TUI 和 fallback 行模式暴露过程。
- TUI 和 fallback 行模式不直接依赖 Agent 内部循环细节。
- 用户取消时，Agent 通过协作式取消在安全边界停止循环。

## 非功能要求
- Agent Loop 应保持可观测，工具调用、工具结果、状态变化和最终回答都应能被界面消费。
- Agent 与 UI 应通过事件流解耦，后续新增 UI 不需要重写循环逻辑。
- 循环必须有步数上限，避免模型无限调用工具。
- 工具失败不应导致程序崩溃，应作为结构化结果回灌给模型。
- 工具结果顺序应稳定，不受并发完成顺序影响。
- Plan Mode 必须保证不会实际写文件、改文件或执行命令。
- 本章实现应保留后续接入权限系统、上下文压缩和更复杂提示词的扩展空间。

## 设计骨架
MewCode 第四章按以下层次组织：

1. Agent 事件层
   - 负责定义 Agent 与界面之间的事件边界。
   - 负责表达状态、文本、工具开始、工具结束、完成、取消和错误。

2. Provider 工具响应层
   - 负责把供应商返回的一个或多个工具调用转换为统一结构。
   - 负责在流式过程中透传文本增量，并在响应结束后给出完整工具调用列表。

3. 会话层
   - 负责保存用户消息、最终 assistant 文本、assistant 工具调用和工具结果。
   - 负责保持工具调用与工具结果之间的稳定对应关系。

4. Agent Loop 编排层
   - 负责执行 ReAct while 循环。
   - 负责判断继续或停止。
   - 负责将模型输出、工具执行和结果回填串联起来。

5. 工具批处理层
   - 负责把一轮模型响应里的工具调用分为安全读工具和不安全工具。
   - 负责并发执行安全读工具、串行执行不安全工具。
   - 负责按原始工具调用顺序写回结果。

6. 模式控制层
   - 负责维护正常执行模式和 Plan Mode。
   - 负责在 Plan Mode 下限制工具能力并引导模型输出计划。

7. Textual 与行模式交互层
   - 负责消费 AgentEvent。
   - 负责展示多步工具状态、最终回答、取消和错误。
   - 负责处理模式切换命令。

## 停止条件
- 模型没有请求工具，返回最终文本。
- 模型显式结束当前轮次。
- Agent 达到工具步骤上限。
- 用户触发取消。
- 发生不可恢复错误。

## 权限与边界
- 本章不实现完整权限系统。
- 正常执行模式下，写文件、改文件和命令执行不再要求用户逐步确认。
- Plan Mode 下只读工具可用，不安全工具被拦截。
- 文件和命令仍受第三章已有工具上下文、路径边界、超时和输出截断保护。

## Out of Scope
- 不做完整权限系统。
- 不做上下文压缩。
- 不做用户确认机制。
- 不做子 Agent 或任务委派。
- 不做复杂系统提示词组装。
- 不做长期模式配置持久化。
- 不做项目索引数据库。
- 不做 Git 自动提交或自动推送。
- 不做多 Agent 协作。

## 完成定义
当用户提出需要多步操作的任务时，MewCode 可以在同一轮请求内自主搜索、读取、写入或运行命令，并根据工具结果继续决定下一步，直到给出最终回答，则本章达到核心完成标准。验收还需要证明：同一模型响应可以包含多个工具调用，读工具可批量执行，不安全工具串行执行，Plan Mode 不产生写入或命令副作用，TUI 和行模式都消费统一事件流，取消和步数上限可观测。
