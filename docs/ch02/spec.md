# MewCode 第二章规格说明：常驻式 AI Coding Agent 终端界面

## 背景
MewCode 是一个使用 Python 开发的终端 AI 编程助手。第二章的目标从“普通命令行问答”升级为“常驻式 AI Coding Agent 终端界面”：用户启动后进入一个现代化终端应用，界面持续驻留，底部固定输入，上方展示对话、状态和模型输出。

这一章仍然不进入 tool use、文件操作和代码编辑等 Agent 能力，但要把未来 Coding Agent 的交互外壳搭好：有品牌区、有模式提示、有状态反馈、有真实 LLM 流式回复，并保留多轮对话上下文。

## 目标用户
- 想在终端中使用常驻式 AI 编程助手的开发者。
- 正在学习如何从零构建 Claude Code 类工具的人。
- 需要观察 Provider 抽象、流式输出和 TUI 架构如何组合的开发者。

## 阶段目标
本阶段要交付一个可从终端启动的 MewCode 常驻式 TUI。用户通过配置选择模型后端，启动后进入黑色背景的全屏终端界面，在底部输入问题，上方显示对话历史、处理中状态和真实 LLM 流式回复。对话上下文在当前运行期间保留，退出后不持久化。

## 能力清单
- 用户可以通过终端命令启动 MewCode 并进入常驻式终端界面。
- 界面顶部展示 MewCode 品牌、版本、当前模型和使用状态占位信息。
- 界面底部提供固定输入框，用户可以持续输入问题。
- 对话区域区分用户消息和 AI 回复，用户消息使用醒目标识，AI 回复使用独立标识。
- 当前正在处理的用户消息会被高亮，帮助用户识别当前请求。
- AI 回复期间显示 Thinking、Coding、Done 等处理状态。
- Thinking 和 Coding 状态具有动态变化效果，体现程序正在工作。
- AI 回复以流式方式逐步显示，而不是等待完整结果后一次性输出。
- MewCode 在当前运行期间保留多轮消息，让后续问题可以引用前文。
- MewCode 可以通过 YAML 配置切换 Anthropic Claude 与 OpenAI 后端。
- MewCode 的模型供应商接入通过统一抽象组织，方便后续增加新后端。
- MewCode 支持为 Claude 后端开启扩展思考能力。
- 界面为后续 plan 模式、auto 模式等 Agent 模式预留提示位置。
- MewCode 在本阶段不执行本地工具、不读取项目文件、不修改代码。

## 非功能要求
- 终端界面应更接近现代 AI Coding CLI，而不是传统菜单式 TUI。
- 整体视觉应保持深色背景，并突出品牌、输入区、状态区和消息标识。
- 真实 LLM 流式调用不能让界面失去响应能力。
- 供应商切换不应影响界面交互方式。
- 配置结构应保留扩展空间，后续可加入模式、计费、token 统计和工具能力。
- 对话历史只保留在内存中，避免本阶段引入会话持久化和隐私管理复杂度。
- 错误处理应避免直接向用户暴露 Python traceback。
- 中断操作应让用户能从正在生成的状态回到可继续输入的状态。

## 设计骨架
MewCode 本阶段按以下层次组织：

1. 命令行入口
   - 负责启动应用、加载配置、创建运行所需组件，并进入终端界面。

2. 配置层
   - 负责从用户目录读取 YAML 配置。
   - 负责描述当前选择的协议、模型、服务地址、认证信息以及可选扩展项。

3. Provider 抽象层
   - 负责定义所有模型后端都需要满足的统一流式对话能力。
   - 负责屏蔽不同供应商在请求格式和流式事件上的差异。

4. Provider 实现层
   - 分别适配 Claude 与 OpenAI 的对话协议。
   - 将供应商返回的流式事件转换成统一的文本增量。

5. 会话层
   - 负责保存当前进程内的多轮消息历史。
   - 负责把用户输入和模型回复纳入后续请求上下文。

6. Textual 交互层
   - 负责常驻式全屏终端界面。
   - 负责展示顶部品牌区、对话区、状态行、底部输入框和底部模式提示。
   - 负责把用户输入提交给会话与 Provider，并把流式结果增量更新到界面。

## Out of Scope
- 不做 tool use。
- 不做文件读取、文件写入或代码编辑。
- 不做 shell 命令执行。
- 不做自动任务规划或多步骤 Agent 行为。
- 不实际实现 plan 模式或 auto 模式，只保留界面提示。
- 不做会话历史持久化。
- 不做项目索引、代码库理解或上下文检索。
- 不做图片、语音、文件上传等多模态能力。
- 不做 token 实时统计和真实计费统计。
- 不做多 Agent 协作。

## 完成定义
当用户可以配置一个支持的模型供应商，运行 MewCode 进入 Textual 常驻式终端界面，在底部输入问题，并观察到上方区域显示用户消息、动态处理状态和真实 LLM 流式回复时，本阶段即达到核心完成标准。验收还需要证明：供应商可以切换，多轮上下文生效，Claude 扩展思考可以通过配置启用，界面为后续模式预留提示，且本阶段没有引入任何本地工具执行或代码编辑能力。
