# MewCode 第六章规格说明：权限系统

## 背景
第四章让 MewCode 拥有 Agent Loop，第五章让它拥有更稳定的 Prompt 管线。现在 MewCode 可以自主搜索、读取、写入、编辑和运行命令，但能力越强，风险越高。没有权限系统时，模型可能执行破坏性命令、越权访问工作区外文件，或者在用户只想小修时扩大修改范围。

第六章要给 MewCode 增加一套五层防御的权限系统。危险命令在执行前被硬拦截，文件路径被限制在工作区沙箱内，规则引擎提供细粒度 allow/deny，权限模式表达整体信任等级，人在回路确认作为最后兜底。权限拒绝不会终止 Agent Loop，而是以结构化工具结果回填给模型，让模型有机会调整策略。

## 目标用户
- 想让 MewCode 自动执行任务但仍保留安全边界的开发者。
- 想按项目和本地环境配置不同信任等级的用户。
- 正在学习 Coding Agent 权限系统、沙箱、规则引擎和 HITL 机制的实现者。
- 后续要扩展网络限制、资源配额和审计日志的人。

## 阶段目标
本阶段交付一套工具执行前权限检查系统。所有工具调用在真正执行前都经过统一权限检查器，检查器串联危险命令黑名单、路径沙箱、规则引擎、权限模式和 HITL 确认。危险命令不可被配置放开；路径逃逸必须被拦截；规则文件按本地级、项目级、用户级优先级决策；同一层规则中 deny 优先于 allow；规则未明确命中时由权限模式决定自动放行、自动拒绝或请求用户确认。

用户级规则存放在 `~/.mewcode/permissions.yaml`，项目级规则存放在 `.mewcode/permissions.yaml`，本地级规则存放在 `.mewcode/permissions.local.yaml`。本地规则用于当前项目的个人偏好，应被加入忽略规则；项目规则可以提交给团队共享。权限模式使用 `default`、`acceptEdits`、`plan`、`bypassPermissions` 四档，默认 `default`。用户可以通过快捷键循环切换模式，并在状态栏常驻看到当前模式。HITL 确认支持允许本次、永久允许、拒绝本次三种选择。

## 能力清单
- MewCode 可以在工具执行前统一调用权限检查器。
- 权限检查器可以输出允许、拒绝或需要用户确认三种决策。
- 危险命令检测器可以用正则识别不可逆系统破坏命令。
- 危险命令检测结果不可被规则、模式或用户确认覆盖。
- 路径沙箱可以在解析符号链接后验证路径仍位于项目目录内。
- 文件读写、计划文件写入和路径相关工具都使用同一套路径沙箱判断。
- 敏感文件读取保护可以拦截 `ReadFile` 对 `.env` 文件族的宽泛通配符读取。
- 模型可以读取明确指定的单个 `.env` 候选文件，但不能用通配符一次性扫读环境文件。
- 规则引擎可以加载用户级、项目级和本地级规则。
- 规则引擎可以按工具名和参数模式匹配工具调用。
- 规则结果只有 allow 和 deny 两种。
- 规则优先级为本地级高于项目级，项目级高于用户级。
- 同一层级中 deny 规则优先于 allow 规则。
- 权限模式可以控制规则未命中时的默认行为。
- `default` 模式默认允许安全读操作，对写文件、编辑文件和 Bash 请求确认。
- `acceptEdits` 模式默认允许文件写入和编辑，对 Bash 仍请求确认。
- `plan` 模式只允许规划和只读操作，不允许写文件、编辑文件或 Bash。
- `bypassPermissions` 模式默认允许可执行操作，但仍不能绕过危险命令检测和路径沙箱。
- HITL 确认可以把一次待执行工具调用交给 UI。
- 用户可以选择允许本次、永久允许或拒绝本次。
- 被拒绝的权限决策会作为结构化工具结果回填给模型。
- Agent Loop 在权限拒绝后继续运行，不因拒绝直接崩溃或退出。

## 非功能要求
- 权限检查必须发生在工具真实副作用之前。
- 危险命令检测必须简单、保守、可测试，不能依赖模型判断。
- 路径沙箱必须使用解析后的绝对路径判断，防止符号链接逃逸。
- 规则加载失败应给出可理解错误，不应静默降级到更危险状态。
- HITL 等待不应阻塞 UI 输入恢复和取消逻辑。
- 权限系统应与 Plan Mode 兼容，Plan Mode 的只读约束仍然生效。
- 本章应保留后续审计日志、网络请求限制和资源配额扩展空间。

## 设计骨架
MewCode 第六章按以下层次组织：

1. 危险命令检测层
   - 负责识别高危 Bash 命令。
   - 负责在任何规则和模式之前硬拒绝。

2. 路径沙箱层
   - 负责解析工具参数中的路径。
   - 负责对解析后的真实路径做工作区边界检查。
   - 负责复用现有工具上下文中的路径保护能力。

3. 敏感读取保护层
   - 负责识别对环境文件族的宽泛读取。
   - 负责拒绝通配符形式的 `.env` 文件读取，并提示模型改用明确候选文件名逐个尝试。
   - 负责允许明确单文件路径继续进入后续权限判断。

4. 规则加载层
   - 负责从用户级、项目级和本地级 YAML 文件读取规则。
   - 负责处理文件不存在、格式错误和规则无效。

5. 规则匹配层
   - 负责把工具调用转换成可匹配对象。
   - 负责支持 `工具名(模式)` 形式的精确或 glob 匹配。
   - 负责输出 allow、deny 或未命中。

6. 权限模式层
   - 负责定义四种全局信任等级。
   - 负责在规则未命中时给出默认决策。
   - 负责支持快捷键循环切换模式，并向 UI 暴露当前模式。

7. 权限检查器层
   - 负责串联危险命令、路径沙箱、敏感读取保护、规则匹配、模式决策和 HITL 判断。
   - 负责生成统一的权限决策对象。

8. Agent 事件层
   - 负责把需要用户确认的工具调用作为事件发给 UI。
   - 负责在用户选择后继续执行或回填拒绝结果。

9. UI 交互层
   - 负责渲染确认对话框。
   - 负责支持允许本次、永久允许和拒绝本次。
   - 负责把永久允许的精确规则写入本地规则文件。
   - 负责在状态栏常驻显示当前权限模式。

## 规则与配置边界
- 用户级规则文件为 `~/.mewcode/permissions.yaml`。
- 项目级规则文件为 `.mewcode/permissions.yaml`。
- 本地级规则文件为 `.mewcode/permissions.local.yaml`。
- 本地级规则文件不应提交到 Git。
- 规则写成 `工具名(模式)`。
- Bash 规则模式匹配 `command` 参数。
- 文件工具规则模式匹配路径参数。
- 读搜索工具规则模式匹配主要查询或路径模式参数。
- `ReadFile` 只能读取明确的单个文件路径，不能把 `*.env*` 当成批量读取模式。
- `.env`、`.env.local`、`.env.example`、`.env.development`、`.env.production` 这类明确候选文件可以由模型逐个尝试读取。
- 规则结果只支持 allow 和 deny。
- HITL 的“永久允许”会生成精确 allow 规则，写入 `.mewcode/permissions.local.yaml`。

## 权限模式边界
- 默认模式为 `default`。
- `default` 是常规开发模式，读操作顺滑，写操作和命令需要确认。
- `acceptEdits` 适合用户已经信任当前代码修改方向，文件写入和编辑默认允许，Bash 仍需确认。
- `plan` 是规划模式，只允许只读和规划，不执行写文件、编辑文件或 Bash。
- `bypassPermissions` 适合临时高自动化场景，但仍不能执行危险命令或逃出沙箱。
- 权限模式可以通过快捷键循环切换，UI 状态栏应常驻显示当前模式。

## HITL 行为边界
- HITL 只处理可以被用户放行的权限不确定项。
- 危险命令和路径逃逸不会进入 HITL，直接拒绝。
- 用户拒绝后，工具不会执行，拒绝原因回填给模型。
- 允许本次只影响当前工具调用。
- 永久允许会把当前工具调用转换成精确 allow 规则，写入当前项目的本地规则文件。
- 拒绝本次只拒绝当前工具调用，不写入配置。

## Out of Scope
- 不做网络请求限制。
- 不做资源用量配额。
- 不做审计日志。
- 不做远程策略同步。
- 不做多用户权限模型。
- 不做操作系统级容器沙箱。
- 不做权限规则图形化编辑器。
- 不做策略签名和供应链校验。

## 完成定义
当所有工具调用都会在执行前经过统一权限检查，危险命令和路径逃逸被硬拦截，规则和权限模式可以影响普通工具调用，UI 可以对待确认操作进行 HITL 决策，并且权限拒绝会回填给模型继续 Agent Loop 时，本章达到核心完成标准。验收还需要证明：三层规则文件优先级正确，同层 deny 优先于 allow，四种权限模式行为可观测，永久允许能写入本地规则文件，Plan Mode 与权限系统不会互相绕过。
