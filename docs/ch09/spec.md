# MewCode 第九章规格说明：跨会话记忆系统

## 背景
第八章给 MewCode 加入了上下文管理能力，Agent 可以在一个会话里通过工具结果落盘、自动压缩和手动压缩持续工作更久。但这些能力仍然属于单次会话：终端关闭后，当前项目的架构讨论、用户反复强调的偏好、已经形成的约定和会话现场都会丢失。

第九章要给 MewCode 加入跨会话记忆系统。它通过项目指令文件、会话持久化和自动记忆三层机制，让新会话可以自动恢复项目知识、用户偏好和可继续工作的历史现场，把 MewCode 从“每次重新认识项目”升级成“越用越懂当前项目和用户习惯”的 Agent。

## 目标用户
- 希望 MewCode 在新会话中继续遵循项目技术栈、代码规范和协作约定的用户。
- 经常跨天处理同一项目，希望恢复之前任务背景和会话现场的开发者。
- 希望 Agent 记住个人表达偏好、编码偏好和纠正反馈的人。
- 正在学习长期记忆、会话恢复、指令文件加载和上下文注入设计的开发者。

## 能力清单
- MewCode 可以发现并加载用户级和项目级的 `MEWCODE.md` 指令文件。
- 项目私有指令优先于项目根指令，项目指令优先于用户全局指令。
- 指令文件支持 `@include` 形式的模块化引入。
- 指令文件加载会限制 include 范围、深度和循环引用，避免越界读取和无限展开。
- 指令文件内容会作为动态上下文注入对话消息，不污染稳定 system prompt cache。
- MewCode 可以把会话消息追加写入 JSONL 会话存档。
- 会话存档可以在程序崩溃后尽量恢复，坏行不会破坏整段历史。
- 会话恢复会校验工具调用和工具结果的链路完整性。
- 会话恢复后如果上下文过大，可以先接入现有上下文压缩能力再继续对话。
- 会话恢复时可以提示模型距离上次会话已经过去多久，避免把旧状态误当成刚发生。
- MewCode 可以定期清理过期会话存档。
- MewCode 可以在 Agent 自然完成一轮任务后自动提取值得长期保留的信息。
- 自动记忆可以区分用户偏好、纠正反馈、项目知识和参考资料。
- 用户级记忆和项目级记忆分开保存，并在新请求前加载相关索引。
- 记忆索引会以轻量摘要形式注入上下文，让模型像已经读过记忆一样工作。
- 用户可以通过 `/session` 管理历史会话。
- 用户可以通过 `/memory` 查看、刷新、开关或删除记忆。
- TUI 和 line mode 都可以消费会话与记忆相关状态，并保持现有 Agent Loop 体验。

## 非功能要求
- 指令文件、会话存档和记忆注入必须走 messages 通道，不能破坏第五章建立的 system prompt cache 策略。
- 会话写入必须以追加为主，避免一次异常导致完整历史文件损坏。
- 会话恢复必须保守，遇到无法证明完整的工具链路时优先截断到安全位置。
- 自动记忆不能阻塞最终回复，也不能因为记忆提取失败而让用户任务失败。
- 自动记忆不能保存明显敏感信息、密钥、令牌或 `.env` 类内容。
- 项目级状态文件必须位于本地 `.mewcode/` 状态目录，避免污染项目源文件结构。
- 用户级记忆和项目级记忆必须隔离，避免把某个项目的私有知识写成全局偏好。
- 记忆索引需要控制体积，避免长期记忆本身变成新的上下文负担。
- 所有恢复、跳过、截断和记忆失败都要可观测，方便 UI 或日志解释当前状态。
- 第九章不能绕过现有权限系统和上下文管理系统。

## 设计骨架
1. 指令文件加载层
   - 发现用户级、项目根和项目私有指令文件。
   - 按优先级拼接为可注入上下文。
   - 展开安全的 `@include` 引用，并拦截越界、循环和过深嵌套。

2. 会话存档层
   - 将会话事件和消息追加写入 JSONL 存档。
   - 通过扫描 JSONL 生成会话列表、标题、消息数和时间信息。
   - 不依赖单独 meta 文件维护同步状态。

3. 会话恢复层
   - 从 JSONL 重建 ChatSession。
   - 跳过坏行并校验工具调用链路。
   - 对不完整尾部、孤儿工具结果和超大上下文执行保守恢复策略。

4. 会话生命周期层
   - 创建新会话、列出历史会话、恢复指定会话、删除会话和清理过期会话。
   - 与已有会话隔离目录协作，复用现有大工具结果落盘位置。

5. 自动记忆提取层
   - 在 Agent 自然结束后分析本轮对话。
   - 提取用户偏好、纠正反馈、项目知识和参考资料。
   - 本章先使用可测试的本地提取器，后续可以替换为 LLM 提取和去重。

6. 记忆存储层
   - 用户级记忆写入用户目录。
   - 项目级记忆写入项目 `.mewcode/`。
   - 每条记忆保持可读 Markdown 形式，并维护轻量索引。

7. Prompt 注入层
   - 把指令文件、记忆索引和会话恢复提醒封装为 system-reminder 消息。
   - 在每轮请求前注入，不进入稳定 system prompt。
   - 与 Plan Mode、环境上下文和上下文压缩恢复消息共同工作。

8. REPL 命令层
   - `/session` 提供会话查看与恢复操作。
   - `/memory` 提供记忆查看、刷新、开关和删除操作。
   - TUI 和 line mode 使用同一套底层能力。

## 配置边界
- 自动记忆默认开启，但用户可以通过配置或命令关闭。
- 用户级配置仍来自用户目录。
- 项目级本地状态默认使用 `.mewcode/`。
- 项目级配置仍遵循现有项目配置文件策略。
- 记忆、会话和工具结果缓存不应提交到 Git。

## Out of Scope
- 不做向量数据库。
- 不做 RAG 检索。
- 不做跨项目语义召回。
- 不做团队共享记忆同步。
- 不做云端记忆服务。
- 不做复杂记忆评分和机器学习排序。
- 不做真实审计日志系统。
- 不做对 MCP Resources 的长期索引。
- 不做自动从 Git 历史生成项目记忆。

## 完成定义
当 MewCode 启动和每轮请求前可以加载 `MEWCODE.md` 指令与记忆索引，新会话能继承项目知识和用户偏好；会话可以追加存档、列出、恢复并在异常尾部下保守修复；Agent 自然完成后可以异步提取长期记忆；用户可以通过 `/session` 和 `/memory` 管理这些能力；且所有动态信息都通过 messages 通道注入时，本章达到核心完成标准。
