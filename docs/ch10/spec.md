# MewCode 第十章规格说明：Slash Command 内置命令框架

## 背景
前几章让 MewCode 具备了 Agent Loop、权限、MCP、上下文管理和跨会话记忆。但一些日常操作仍然混在自然语言对话里：用户想清屏、查看状态、切换模式或压缩上下文时，模型可能认真回复却不执行真实本地操作，还会消耗 token。

第十章要把常用斜杠命令变成确定性的本地控制面。所有以 `/` 开头的已知命令先由本地命令框架解析和分发，只有明确属于提示词命令的输入才进入 Agent Loop。

## 目标用户
- 希望清屏、查状态、切模式等操作快速确定执行的 MewCode 用户。
- 希望减少无意义 token 消耗的重度 Agent 使用者。
- 希望学习终端命令注册、分发、补全和 UI 解耦设计的开发者。
- 希望未来扩展 Skill 系统前先拥有稳定命令底座的人。

## 能力清单
- MewCode 可以注册、查找、列举和补全内置 slash command。
- 命令解析对命令名大小写不敏感，并保留命令参数。
- 未知 slash command 不进入 Agent Loop，而是提示用户查看帮助。
- 命令元数据可以描述名称、别名、用途、用法和可见性。
- 启动阶段会检测命令名和别名冲突，避免运行时行为不确定。
- 命令可以按本地操作、UI 状态操作和提示词操作分发。
- 本地操作和 UI 状态操作不会写入会话历史，也不会调用 LLM Provider。
- 提示词操作可以把预设任务说明送入 Agent Loop。
- TUI 和 line mode 使用同一套命令分发逻辑。
- 命令处理不依赖具体 UI 渲染实现。
- 用户可以通过 `/help` 查看可用命令。
- 用户可以通过 `/clear` 清空当前界面显示。
- 用户可以通过 `/plan` 和 `/do` 切换规划与执行模式。
- 用户可以通过 `/compact` 触发上下文压缩。
- 用户可以通过 `/session` 和 `/memory` 管理跨会话状态。
- 用户可以通过 `/permission` 查看或切换权限模式。
- 用户可以通过 `/status` 查看当前运行状态。
- 用户可以通过 `/review` 触发代码审查提示词。
- TUI 输入框支持 slash command 补全。
- 状态栏可以展示当前 Agent mode 和 permission mode。

## 非功能要求
- 命令框架必须可测试，不依赖真实终端或真实 LLM。
- 命令解析和命令执行要分层，避免在 UI 里继续堆分支。
- 现有命令行为应保持兼容，避免破坏已有工作流。
- 本地命令必须快速返回，不触发 Agent Loop。
- 提示词命令必须显式可识别，避免未知命令误入模型。
- UI 清屏不能删除会话、记忆、工具结果或上下文历史。
- 状态栏更新必须和模式切换保持同步。
- 补全只暴露公开命令，不暴露隐藏兼容命令。

## 设计骨架
1. 命令定义层
   - 定义命令元数据、命令分类和处理入口。
   - 区分公开命令和隐藏兼容命令。

2. 命令注册层
   - 负责注册内置命令、检测冲突、按名称或别名查找命令。
   - 提供列举和补全候选。

3. 命令解析层
   - 识别 slash command 输入。
   - 提取命令名和参数。
   - 对未知命令返回可观测结果。

4. 命令执行层
   - 根据命令分类产生本地动作、UI 动作或 Agent prompt 动作。
   - 保持命令处理与具体 TUI/line mode 渲染解耦。

5. UI 控制层
   - 抽象显示消息、清屏、模式切换、权限切换、状态查询和 Agent 驱动。
   - TUI 和 line mode 分别实现同一组能力。

6. 内置命令层
   - 注册高频命令。
   - 兼容现有压缩、会话、记忆和模式切换命令。

7. 补全层
   - 根据当前输入前缀提供候选。
   - TUI 对单候选直接补全，对多候选显示候选提示。

## Out of Scope
- 不做用户自定义命令。
- 不做动态 prompt 生成配置。
- 不做命令级权限系统。
- 不做远程命令市场。
- 不做 shell 风格管道和重定向。
- 不做命令宏录制。
- 不做 Skill 系统。

## 完成定义
当 MewCode 的 slash command 由统一注册中心解析和分发，TUI 与 line mode 都先拦截已知 slash command，十个内置命令可用且本地命令不触发 LLM，未知 slash command 不进入 Agent Loop，TUI 支持基础 Tab 补全，状态栏能同步显示模式变化，并且现有 `/compact`、`/plan`、`/do`、`/session`、`/memory` 行为保持兼容时，本章达到核心完成标准。
