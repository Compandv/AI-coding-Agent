# MewCode 第八章规格说明：上下文管理

## 背景
前几章让 MewCode 具备了 Agent Loop、Prompt 管线、权限系统和 MCP 外部工具接入能力。Agent 可以连续读文件、跑命令、调用工具并根据结果继续推进任务，但上下文窗口仍然有限。随着工具结果、对话历史和中间观察不断累积，Token 消耗会持续升高，最终导致请求失败、模型遗忘关键状态，或者因为上下文过大而明显变慢。

第八章要给 MewCode 增加上下文管理能力。它通过三层策略控制对话体积：先压缩大工具结果，再用结构化摘要替换旧历史，最后提供手动命令让用户观察和控制上下文状态。目标是让 Agent 能在有限 Token 预算内长时间工作，而不是聊几轮或读几个大文件就撞上上下文上限。

## 目标用户
- 想让 MewCode 连续执行长任务而不频繁中断的开发者。
- 经常让 Agent 读取大量代码、日志、测试输出或 MCP 工具结果的用户。
- 正在学习 Coding Agent 上下文压缩、摘要恢复和 Token 预算控制的实现者。
- 后续要扩展长期记忆、上下文检索和跨会话状态恢复的人。

## 能力清单
- MewCode 可以近似估算当前会话、工具结果和 Prompt Payload 的 Token 占用。
- Token 估算可以结合最近一次 API usage 作为锚点，后续增量用近似规则估算。
- 单个工具结果过大时，完整结果会写入本地会话隔离目录。
- 工具结果落盘后，对话里只保留头部预览、尾部预览、省略说明、stored path 和必要元数据。
- 每个会话拥有独立的上下文缓存命名空间，避免不同对话共享或误用落盘结果。
- 单条消息中的工具结果合计过大时，可以按体积从大到小依次落盘。
- Agent 每次请求模型前都会先运行轻量预防压缩。
- 整体上下文逼近窗口上限时，Agent 可以自动触发摘要压缩。
- 摘要压缩可以按用户轮次或消息组分块，先生成 chunk summary，再合并成 final compact summary。
- 摘要请求不携带工具，避免模型在压缩阶段继续执行工具。
- 压缩过程保留近期原文，避免刚发生的操作被过度概括。
- 压缩后的恢复上下文包含摘要、最近读文件快照、当前可用工具和边界提醒。
- 压缩后的边界提醒会要求模型需要精确内容时重新读取文件或 stored path。
- 用户可以通过 `/compact` 手动触发压缩。
- 用户可以通过 `/compact focus <text>` 指定摘要时重点保留的信息。
- 用户可以通过 `/context` 查看当前上下文估算、阈值、熔断状态和最近压缩结果。
- Provider 返回上下文过长错误时，MewCode 可以触发紧急压缩并重试一次。
- 摘要连续失败时会触发自动压缩熔断，避免 Agent Loop 反复失败。
- 压缩开始、分块摘要、fallback、完成和统计信息可以通过事件流被 UI 观察。
- TUI 和 line mode 都可以消费上下文事件并继续正常对话。

## 非功能要求
- Token 估算要稳定、快速、可测试，但本章不追求精确 tokenizer 级别一致。
- 大工具结果落盘必须发生在结果进入会话历史前，避免先污染上下文。
- 落盘文件路径必须位于项目允许的本地缓存目录内，不能逃逸工作区。
- 不同会话的缓存文件、摘要状态和失败熔断状态必须相互隔离。
- 落盘后的预览必须足够帮助模型理解结果类型和主要内容，但不能继续塞入完整大结果。
- 摘要失败不能破坏原始会话历史。
- 压缩后的历史必须能继续被现有 Provider、Prompt 管线和 Agent Loop 使用。
- 上下文管理不能绕过权限系统，不能借压缩读取或写入权限外文件。
- UI 必须明确区分高质量 LLM 摘要、LLM 失败后的本地 fallback、纯本地 fallback。

## 设计骨架
1. Token 估算层
   - 估算会话消息、工具结果和 Prompt Payload 的 Token 占用。
   - 记录最近一次 Provider usage，作为后续估算锚点。

2. 大结果存储层
   - 把超大工具结果写入会话隔离缓存目录。
   - 生成可回填给模型的头部预览、尾部预览、stored path 和元数据。
   - 确保缓存文件不会被误提交到版本库。

3. 轻量预防层
   - 工具结果进入历史前先检查大小。
   - 请求模型前再次检查历史中仍然过大的工具消息。
   - 优先压缩 Token 占用最高的工具结果。

4. 摘要 Prompt 层
   - 构造专用于上下文压缩的摘要请求。
   - 禁止工具调用，并要求输出固定结构的摘要。
   - 区分分析草稿和正式摘要，只把正式摘要写回会话。

5. 分块摘要层
   - 将旧历史按用户轮次或消息组切成多个 chunk。
   - 每个 chunk 生成局部摘要。
   - 将多个局部摘要合并为最终恢复摘要。

6. Auto-Compact 层
   - 请求前判断整体上下文是否逼近窗口上限。
   - 选择需要摘要的旧消息和需要保留的近期原文。
   - 把旧历史替换为恢复上下文。

7. fallback 与熔断层
   - LLM 摘要失败时生成本地 deterministic summary 兜底。
   - 连续自动摘要失败后熔断自动压缩。
   - 手动压缩和紧急压缩可以绕过自动熔断。

8. 事件流层
   - 向 UI 暴露压缩开始、分块开始、分块完成、fallback、压缩完成、失败和统计事件。
   - 让 TUI 和 line mode 能在不耦合压缩实现的情况下展示状态。

9. 命令接入层
   - `/compact` 触发手动压缩。
   - `/compact focus <text>` 触发带重点提示的手动压缩。
   - `/context` 只读展示上下文状态，不触发压缩。

10. Agent Loop 集成层
    - 每轮模型请求前执行上下文管理。
    - 工具结果写入历史前处理大结果。
    - 在上下文过长错误时执行紧急压缩并重试一次。

## 摘要内容边界
结构化摘要应覆盖以下信息：

- 当前任务目标。
- 用户原话和硬约束。
- 已完成的关键动作和结论。
- 已读文件。
- 已写入或编辑的文件。
- 已执行的重要命令和工具结果结论。
- 错误、修复和关键决策。
- 未完成事项和下一步建议。
- 权限模式、落盘结果路径、边界提醒和不能重复犯的错误。

摘要不应伪造未读取过的文件内容，不应把工具输出预览扩写成完整事实，不应包含压缩阶段的分析草稿。

## 配置边界
- 上下文配置属于主配置的一部分。
- 用户可以调整上下文窗口、自动压缩余量、手动压缩余量、工具结果落盘阈值、预览大小、分块摘要预算和 focus 最大长度。
- 本地上下文缓存目录用于存放大工具结果和压缩相关临时文件。
- 本地上下文缓存目录下按会话划分子目录。
- 本地上下文缓存目录不应提交到 Git。

## Out of Scope
- 不做精确 tokenizer。
- 不做机器学习优化的压缩策略。
- 不做跨会话长期记忆。
- 不做语义向量检索。
- 不做自动上下文分片召回。
- 不做 MCP Resources 的上下文索引。
- 不做审计日志和压缩历史回滚 UI。
- 不做按模型供应商分别调优的复杂上下文策略。

## 完成定义
当 MewCode 可以在每次模型请求前估算上下文体积，自动把大工具结果落盘，必要时触发分块摘要压缩并把压缩后的历史写回会话，用户可以通过 `/compact`、`/compact focus` 和 `/context` 手动控制与观察上下文状态，压缩失败不会破坏 Agent Loop，且 TUI 和 line mode 都能观察到压缩事件时，本章达到核心完成标准。
